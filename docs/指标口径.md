# 商析助手指标口径

这是用于个人学习和演示的模拟电商项目。所有订单、客户名称和金额均由固定随机种子生成，不代表真实经营结果。

数据覆盖2026-04-01至2026-10-15；相对日期以固定的2026-10-16为基准。这样录屏、验收和面试演示可重复。将来接真实库时，需要替换此日期机制，而不是只更改界面日期。

| 指标 | 计算口径 | 关键限制 |
|---|---|---|
| 有效销售额 | `SUM(orders.paid_amount)`，仅paid/completed | 全额退款和取消订单不计入 |
| 有效订单数 | 有效状态订单数 | 连接明细时用`COUNT(DISTINCT order_id)` |
| 客单价 | 有效销售额 ÷ 有效订单数 | 分母为0则无可计算值 |
| 购买客户数 | 有效订单的去重客户数 | 不能按明细行数统计 |
| 销量 | 有效订单明细的`SUM(quantity)` | 按下单日期归属 |
| 商品/品类销售额 | 有效明细的`SUM(line_paid_amount)` | 不可JOIN明细后求订单总金额之和 |
| 估算商品毛利 | 有效明细实付减去`quantity * unit_cost` | 使用历史成本，不含物流、税费、运营成本；不是净利润 |
| 全额退款订单率 | refunded订单数 ÷ paid/completed/refunded订单数 | 取消订单不进入分母，输出百分数 |
| 全额退款金额 | 下单日期范围内订单的`SUM(refund_amount)` | 没有退款发生日，不能冒充按退款日统计 |

`paid_amount`保留已退款订单的原付款金额；`refund_amount`在全额退款时等于原付款额。`refunded`状态只模拟全额退款，没有部分退款。

时间过滤使用下单时间、左闭右开区间。例如9月为`ordered_at >= '2026-09-01' AND ordered_at < '2026-10-01'`。未指定时间的普通查询默认最近30天：2026-09-16至2026-10-15，并应在回答中说明。

当前目录价`products.list_price`不等于历史成交金额。订单明细保存价格、成本和分摊后实付金额。退款和取消记录保留在样本中，用于检验筛选逻辑。

不支持库存、广告ROI、访问转化率、部分退款、未来预测和复购率。复购率既需要明确时间窗口和买家定义，也涉及当前查询约束之外的实现，不能仅让模型猜一个公式。

多表求和示例：

```sql
-- 正确：每个商品明细自己的实付金额
SELECT p.category, ROUND(SUM(i.line_paid_amount), 2) AS sales_amount
FROM orders o
JOIN order_items i ON o.order_id = i.order_id
JOIN products p ON i.product_id = p.product_id
WHERE o.status IN ('paid', 'completed')
  AND o.ordered_at >= '2026-09-01'
  AND o.ordered_at < '2026-10-01'
GROUP BY p.category
ORDER BY sales_amount DESC
LIMIT 10;
```

如果改成`SUM(o.paid_amount)`，一笔包含三件不同商品的订单会把整单金额累加三次。验收Q01和Q12专门检查这一问题。
